# reviewctl: quick reference

Commands for reviewing a branch. See [`reviewctl-agent-guide.md`](reviewctl-agent-guide.md) for safety and evidence requirements.

## Setup

From `branch-review` root:

```bash
bun install --frozen-lockfile
export REVIEWCTL_CORE_CLI_PATH="$(pwd)/mini-services/reviewctl/src/index.ts"
reviewctl() { bun "$REVIEWCTL_CORE_CLI_PATH" "$@"; }
reviewctl help
```

From **another repository**, set `REVIEWCTL_CORE_CLI_PATH` to the absolute path of the `branch-review` CLI before changing directories, enable `REVIEWCTL_SAFE_MODE=1`, and run `reviewctl doctor`. This keeps generated artifacts in a separate per-repository location. For the optional installed wrappers, follow [`reviewctl-quick-start.md`](../reviewctl-quick-start.md).

## Full review preparation

Internal checkout (clean branch or worktree):

```bash
reviewctl init --create --base main --target HEAD
reviewctl explore context --force
reviewctl explore diff --force
reviewctl plan --plan-path docs/plans/relevant-plan.md
reviewctl run
reviewctl status
```

In an **external repository with safe mode enabled**, use `reviewctl init --base main` instead of `init --create` if you do not want a new branch.

`run` **generates handoff requests; it does not execute reviewers or linters**. Execute those separately, preserving real exit codes, then ingest their nonempty reports:

```bash
reviewctl ingest --agent code-reviewer --input /absolute/path/to/agent.md
reviewctl ingest --static biome --input /absolute/path/to/biome.txt
reviewctl verdict --json
```

Use the agent and static-tool names requested by the current plan; the above are examples, not universal requirements.

## Valid decisions

- Plan-source statuses: `FOUND`, `MISSING`, `AMBIGUOUS` (there is no `AUTOGENERATED`).
- A usable plan file may be generated without a matched source plan, but an `ALIGNED` drift state must still be established before a review can `PASS`.
- `run --no-plan` and `run --allow-drift` are diagnostic controls, not merge authorization.
- `verdict --allow-incomplete` cannot turn missing or invalid required evidence into `PASS`.
- Empty static output is `UNKNOWN`, not evidence of a passed check.
- `PASS` is a **local review** result; even then `merge_ready` remains `false`. Check the GitHub PR and required approvals separately.

## Failure recovery

```bash
reviewctl status --json
reviewctl explore context --force
reviewctl explore diff --force
reviewctl plan --plan-path docs/plans/relevant-plan.md
```

If a report fails contract validation, repair it and re-ingest with `--overwrite`. If HEAD changed, rerun reviewers and static checks against the new HEAD. Do not bypass unresolved findings.
